# 护龄 —— 基于视觉的人类动作状态实时分类系统

## 技术报告

---

## 一、项目概述

**项目名称**：护龄（HuLing）—— 基于计算机视觉与机器学习的实时人体状态监测系统

**核心功能**：通过单目摄像头实时采集人体画面，利用 MediaPipe Pose 提取 33 个人体关键点坐标，经特征工程转换为 98 维姿态特征向量，再送入训练好的随机森林（Random Forest）分类器，实现对以下 6 种人体状态的实时识别：

| 状态 ID | 状态名称 | 告警等级 | 说明 |
|---------|---------|---------|------|
| 0 | walking（行走） | 正常 (0) | 正常站立/行走/活动 |
| 1 | sitting（静坐） | 正常 (0) | 坐姿休息 |
| 2 | lying（躺卧） | 正常 (0) | 正常躺卧（如睡觉） |
| 3 | long_sit（久坐） | 低 (1) | 长时间保持坐姿不动（>30帧约2.5秒）|
| 4 | abnormal（异常姿态） | 中 (2) | 姿态异常，需关注 |
| 5 | fall（跌倒） | 高 (3) | 检测到跌倒事件，红色闪烁告警 |

**技术路线**：MediaPipe Pose（关键点检测）→ 多维度特征工程（98维）→ 随机森林分类器 → 实时可视化叠加

## 三、核心算法流程

### 3.1 整体管道

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐    ┌──────────┐
│ 摄像头帧  │──→│ MediaPipe     │──→│ 特征提取器    │──→│ 标准化器  │──→│ 分类器   │──→ 状态+置信度
│ 640×480  │    │ Pose检测     │    │ (98维特征)   │    │ Standard  │    │ Random   │
│          │    │ 33个关键点   │    │              │    │ Scaler    │    │ Forest   │
└──────────┘    └──────────────┘    └──────────────┘    └──────────┘    └──────────┘
                                             │
                                             ▼
                                    ┌──────────────┐
                                    │ 可视化叠加    │
                                    │ +骨架+概率条  │
                                    │ +告警闪烁    │
                                    └──────────────┘
```

### 3.2 处理流程详述

**Step 1：MediaPipe Pose 关键点检测**
- 使用 Google MediaPipe Pose 模型（model_complexity=1，均衡速度与精度）
- 从每帧 640×480 画面中检测 33 个人体关键点（Landmark）
- 每个关键点包含：`(x, y, z, visibility)` —— 2D归一化坐标、深度、可见度置信度

**Step 2：特征工程（98 维）**
特征提取器将 33 个关键点转换为 98 维数值特征向量，分为 6 个模块：

| 模块 | 维度 | 内容 |
|------|------|------|
| 躯干基础特征 | 6 | 质心坐标(x,y)、躯干长度、躯干角度、肩高、髋高 |
| 关节点归一化 | 66 | 33 点 × 2 维 (x,y)，以髋部为零点归一化 |
| 身体角度特征 | 8 | 左右膝角、肘角、髋角、肩角 |
| 姿态结构特征 | 8 | 宽高比、相对高度、对称性、脚-髋距、手高、可见度、头倾斜 |
| 运动特征 | 4 | 质心位移量、速度方向、关键点总位移、姿态变化率 |
| 传感器槽位 | 6 | 预留加速度计/心率/血氧/体温接口（当前填0） |

**特征设计的关键思想：**
- **髋部归一化**：以髋部中点为原点对关节点坐标做相对化处理，消除人在画面中的绝对位置影响
- **肩宽尺度因子**：用肩宽做归一化分母，使不同体型、不同距离的人映射到统一尺度
- **躯干角度**：躯干与垂直线的夹角是区分站/坐/躺的核心特征（站≈0°，躺≈80-90°）
- **宽高比**：人体包围盒的高/宽比，站立时 >1，躺倒时 <0.5，是最强区分特征之一

**Step 3：标准化 + 分类**
- `StandardScaler` 将 98 维特征标准化为均值 0、方差 1 的分布
- 随机森林（100 棵树，最大深度 12，使用 balanced class_weight）输出 6 类概率分布
- 取最大概率类别作为当前帧的状态

**Step 4：概率平滑（消抖）**
- 对最近 7 帧的预测结果取众数，避免单帧误检导致的闪烁
- 跌倒告警持续 3 秒后自动解除

**Step 5：可视化渲染**
- 顶部状态栏：当前状态（颜色编码） + 置信度百分比 + 告警等级
- 右侧概率柱状图：6 类状态实时概率对比
- 底部时间线：最近 100 帧的状态历史
- 跌倒闪烁：画面整体红色半透明覆盖 + 大字 "FALL DETECTED!"

## 四、模型训练流程

### 4.1 训练数据来源

- **自采集数据**：`data_capture.py` 在摄像头前做动作 + 按数字键 1-6 打标签
- **开源数据集**：通过 `dataset_loader.py` 加载 UR Fall Detection (URFD)、Le2i 等公开跌倒检测数据集
- **数据格式**：统一 CSV 文件，每行 = 98 维特征 + label（0-5）+ label_name

### 4.2 训练参数

| 参数 | 值 |
|------|-----|
| 分类器 | Random Forest |
| 决策树数量 | 100 |
| 最大深度 | 12 |
| 类别权重 | balanced（自动处理类别不平衡） |
| 测试集比例 | 20% |
| 随机种子 | 42 |
| 特征标准化 | StandardScaler |
| 交叉验证 | 5 折 StratifiedKFold |

### 4.3 模型持久化

训练产物保存为 `.joblib` 格式，包含三个组件：
```python
{
    "model": RandomForestClassifier,  # 分类器
    "scaler": StandardScaler,         # 标准化器
    "metrics": {                      # 评估指标
        "accuracy": 0.xxx,
        "model_type": "random_forest",
        ...
    }
}
```

## 五、实时推理主程序 (inference.py)

### 5.1 类结构

```
main()
  ├── 命令行参数解析 (camera索引, model名称, --no-display等)
  ├── 创建 InferenceEngine 实例
  │     ├── 加载 joblib 模型包 (model + scaler)
  │     ├── 初始化 FeatureExtractor (use_motion=True, smooth_window=0)
  │     └── 初始化 MediaPipe Pose (model_complexity=1)
  ├── 打开摄像头 (Windows: CAP_DSHOW 后端)
  ├── 创建显示窗口 + 摄像头热身（丢弃前10帧）
  │
  └── 主循环 (按 Q 退出):
        ├── cap.read() 读取一帧
        ├── cv2.flip() 水平镜像翻转
        ├── engine.process_frame(frame) 推理
        │     ├── MediaPipe pose.process() → 33 关键点
        │     ├── landmarks_from_mediapipe() → List[Landmark3D]
        │     ├── extractor.extract_with_motion() → 98 维特征
        │     ├── scaler.transform() → 标准化
        │     ├── model.predict_proba() → 6 类概率
        │     └── _smooth_prediction() → 7帧众数消抖
        ├── 告警判断 (跌倒/久坐)
        ├── _draw_overlay() → 可视化渲染
        ├── cv2.imshow() → 显示
        └── cv2.waitKey(1) → 按键检测
```

### 5.2 运行方式

```bash

# 指定外接摄像头

```

## 六、调试过程中发现并解决的问题

### 问题 1：摄像头窗口无画面

**现象**：程序启动后摄像头窗口弹出，但画面全黑。

**根因**：HP 笔记本内置摄像头的物理隐私挡板（Privacy Shutter）处于关闭状态，镜头被物理遮挡。MediaPipe 虽然能检测到摄像头设备（cap.isOpened() = True），但读取到的帧全部为黑色。

**解决**：打开摄像头上方的物理隐私挡板滑块。

---

### 问题 2：打开隐私挡板后窗口不弹出

**现象**：物理挡板打开后，程序打印完启动信息就卡住，窗口不再弹出。此前挡板关闭时反而能弹出窗口。

**根因**：摄像头使用 Windows 默认的 MSMF（Media Foundation）视频后端。在物理挡板状态切换后，MSMF 后端的 `cap.read()` 调用进入阻塞状态（死等数据），永远无法返回，因此程序卡在 `cap.read()` 这一行，走不到后面的 `cv2.imshow()`。

**解决**：将摄像头初始化改为显式指定 `cv2.CAP_DSHOW`（DirectShow）后端：
```python
# 修改前
cap = cv2.VideoCapture(args.camera)

# 修改后（Windows 上使用 DSHOW 后端）
if os.name == 'nt':
    cap = cv2.VideoCapture(args.camera, cv2.CAP_DSHOW)
else:
    cap = cv2.VideoCapture(args.camera)
```
DSHOW 后端对 Windows 摄像头的状态切换兼容性更好，不会阻塞。

---

### 问题 3：窗口闪退 —— 特征维度不匹配（核心问题）

**现象**：修改 DSHOW 后端后，窗口短暂出现后立刻消失。终端输出错误：
```
X has 108 features, but StandardScaler is expecting 98 features as input.
```

**根因分析**：

特征提取器 `FeatureExtractor` 在不同场景下产生的特征维度不一致：

```
训练阶段（use_motion=False, smooth_window=默认值）:
  躯干(6) + 关节点(66) + 角度(8) + 结构(8) + 运动(0) + 传感器(6) = 94 维
  但 scaler 期望 98 维 → 说明训练时实际使用了 use_motion=True + smooth_window=0

推理阶段（use_motion=True, smooth_window=5）:
  躯干(6) + 关节点(66) + 角度(8) + 结构(8) + 运动(4+5×2=14) + 传感器(6) = 108 维
```

差异在于 `smooth_window` 参数。`smooth_window=5` 时，运动特征模块会将最近 5 帧的历史位移数据（共 5×2=10 维）追加到特征向量中，而训练时 `smooth_window=0` 没有这部分历史数据。

| 配置 | 运动特征维度 | 总维度 |
|------|------------|--------|
| smooth_window=0 (训练时) | 4 | **98** |
| smooth_window=5 (推理时) | 14 | **108** |
| 差异 | — | **+10** |

**解决**：将推理时的 `smooth_window` 与训练时对齐：
```python
# 修改前
self.extractor = FeatureExtractor(use_motion=use_motion)

# 修改后
self.extractor = FeatureExtractor(use_motion=use_motion, smooth_window=0)
```

## 八、总结

**技术亮点：**

1. **多维度特征工程**：从 33 个关键点坐标出发，设计了 6 大类共 98 维特征，覆盖空间几何（躯干角度、宽高比）、时序运动（位移、速度）、对称性等多维度信息
2. **髋部归一化 + 肩宽尺度因子**：消除人在画面中的绝对位置和体型差异，使模型对不同站位、不同体型具有鲁棒性
3. **随机森林 + 概率平滑**：树模型可解释性好，7 帧众数消抖有效抑制单帧误检
4. **模块化架构**：特征提取、训练、推理三模块解耦，便于替换模型或特征方案
5. **双后端兼容**：自动识别 Windows 平台并使用 DSHOW 后端，避免 MSMF 的兼容性问题
