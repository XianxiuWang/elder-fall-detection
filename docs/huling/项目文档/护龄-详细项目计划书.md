### 一、系统工作原理（工作流程）分析、关键技术/算法原理分析（10分）

#### 1.1 项目背景与问题定义

**社会痛点**：截至2025年底，我国60岁以上人口已超3亿，独居老人突破1亿。跌倒是我国65岁以上老年人伤害死亡的首位原因，发生率约30%。跌倒后的"黄金救援时间"仅30分钟，但现有监护方案存在三大问题：
- **需主动佩戴**：手环类方案遗忘佩戴率高（老人抵触、充电麻烦）
- **成本高昂**：商用方案3000-8000元，难以普及
- **依赖云端**：断网即失效，且存在数据隐私风险

**项目目标**：开发一套"无感、低成本、离线可用"的独居老人居家安全监护系统，支持7类人体状态实时识别（正常行走、坐着/休息、躺卧正常、久坐未动、异常姿态、跌倒/倒地、无人活动），硬件成本控制在200元以内。

#### 1.3 关键技术/算法原理分析

##### 1.3.1 MediaPipe Pose — 人体33关键点提取

**原理**：Google MediaPipe Pose采用两阶段检测-跟踪流水线：
1. **检测阶段**：使用轻量级BlazePose检测器定位人体ROI（基于热图+偏移量回归）
2. **跟踪阶段**：在ROI内使用关键点回归网络，预测33个关键点的(x, y, z, visibility)

**33关键点覆盖**：鼻子、眼（6点）、耳（2点）、嘴（2点）、肩（2点）、肘（2点）、腕（2点）、手（12点）、髋（2点）、膝（2点）、踝（2点）、足（4点）

**选择理由**：
- 运行效率：model_complexity=1模式下30fps实时运行（CPU推理）
- 准确度高：在COCO-WholeBody上训练，关键点检测mAP > 80%
- 无需专用硬件：纯CPU推理，适配Milk-V Duo S

##### 1.3.2 特征工程 — 从33关键点到98维特征向量

这是本项目的**核心创新点**之一。相比直接从原始图像训练端到端分类器，本方案采用"2-stage"策略：

**为什么要2-stage？**
1. **数据效率**：姿态关键点是压缩后的语义表示，33关键点×4维 = 132维，远小于640×480×3 = 921,600维，分类器训练样本需求大幅降低
2. **泛化能力**：关键点位置对光照、背景、衣着变化不敏感，模型更具泛化性
3. **可解释性**：每个特征维度都有物理含义，不像CNN是黑盒

**98维特征的数学原理**：

| 模块 | 维度 | 提取公式 / 方法 |
|------|------|----------------|
| 躯干基础 | 6 | centroid = mean(shoulders + hips); torso_angle = arccos(|vec_torso · vec_vertical|) |
| 关节点归一化 | 66 | 33点 × (x-centroid_x, y-centroid_y) / max(torso_length, 0.01) |
| 身体角度 | 8 | θ_knee_left = angle(hip→knee, knee→ankle); θ_elbow = angle(shoulder→elbow, elbow→wrist) |
| 姿态结构 | 8 | aspect_ratio = width/height; symmetry = (left-right)差值; leg_status 用关键点y值比较 |
| 运动特征 | 4 | Δcentroid = √((x_t - x_t-1)² + (y_t - y_t-1)²); 5帧滑动窗口均值 |
| 传感器槽 | 6 | 预留MPU6050(3轴加速度) + MAX30102(心率+血氧) + MLX90614(体温) |

**为什么98维能区分行走/坐/躺/跌倒？**
- 行走时：质心y值高（站姿0.3-0.4），帧间位移大（>0.02），膝盖弯曲角周期性变化
- 坐姿时：质心y值中等（0.5-0.6），躯干角度近垂直，腿部膝盖弯曲
- 躺卧时：质心y值低（0.7-0.9），躯干角度近水平（与垂线>60°），宽高比变大
- 跌倒时：特征发生突变——质心y值骤降（0.3→0.8），躯干角突变，帧间位移激增

##### 1.3.3 Random Forest 分类器

**算法原理**：
- **Bagging集成**：100棵独立的决策树，每棵使用bootstrap采样训练
- **随机特征选择**：每棵树的每个分裂节点从√98≈10个随机子特征中选择最佳分裂
- **多数表决**：100棵树投票，票数最多的类别作为最终预测

**为什么选Random Forest而非深度学习？**
1. **边缘部署友好**：m2cgen可直接导出为纯C代码（约84,000行），无需任何推理框架
2. **推理速度**：单帧推理<2ms（Milk-V Duo S RISC-V @1GHz），远超深度学习方案
3. **内存占用**：模型参数仅约3MB，完全存储在Flash中
4. **准确率**：在跌倒检测任务上，100棵树精度可达90%+（与小型CNN相当）

##### 1.3.4 多模态融合策略

**双通道交叉验证架构**：
```
视觉通道置信度     传感器通道置信度     最终决策
─────────────────────────────────────────────
    HIGH               HIGH           🔴 直接告警（双通道一致）
    HIGH               LOW            🟡 延迟确认（再观察5帧）
    LOW                HIGH           🟠 可能事件（记录日志、推送提醒）
    LOW                LOW            🟢 正常状态
```

**传感器跌倒检测（阈值法，作为视觉的辅助验证）**：
1. 合加速度计算：`magnitude = √(a_x² + a_y² + a_z²)`
2. 撞击检测：`magnitude > 2.5G` → 标记为疑似撞击事件
3. 姿态确认：500ms内监测pitch/roll角度变化，>60°变化 → 确认跌倒
4. 防误报：正常行走加速度<1.5G；快速坐下有过渡无突变

##### 1.3.5 模型训练与优化流程

```
数据采集 → 特征提取 → 数据集构建 → 模型训练 → C代码导出 → 交叉编译部署
```

**训练流水线**：
1. `.py`端：`collect_data.py`（键盘打标签录制）+ 开源数据集（URFD、SisFall）
2. 特征提取：`feature_extractor.py` 从33关键点提取98维特征 → 保存为CSV
3. 训练：`train_classifier.py` 使用Random Forest，GridSearchCV调参，K折交叉验证
4. 导出：`export_to_c.py` → m2cgen生成纯C RandomForest + scaler_params.h
5. 验证：PC端 `gcc` 编译测试 → Milk-V Duo S交叉编译 → 板载自检

### 二、体系结构设计（10分）

#### 2.1 总体架构选择：边缘计算 + 云边协同

本项目采用**"边缘为主、云端为辅"**的三层架构，核心原则是**所有关键推理在边缘端完成**，云端仅做数据汇聚和展示。

**架构选型理由**：
- **实时性**：跌倒检测需要≤3秒响应，云端往返延迟不可接受
- **隐私安全**：老人居家视频数据不出门，端侧处理后仅上传状态标签
- **离线可用**：断网情况下本地告警仍然工作（蜂鸣器+OLED）
- **成本优化**：无需GPU服务器，边缘端硬件总成本<200元

### 五、算法的创新性（5分）

#### 5.1 算法创新点详细分析

本项目算法创新点可分为三个层面：

**层面一：特征工程方法创新（核心创新）**

不同于业内常用的"端到端深度学习"范式（原始图像→CNN→直接分类），本项目采用了创新的"2-stage推理管线"：

```
标准方案（端到端）:  RGB图像 → CNN/Transformer → 7类输出
                         ↑ 需要数万张标注图片训练，未知场景泛化差

本项目（2-stage）:  RGB图像 → MediaPipe Pose → 33关键点 
                         → 98维特征向量 → RandomForest → 6类输出
                         ↑ 仅需1000-3000帧标注数据，语义级表示泛化好
```

**核心思想**：将"看一张图判断姿态"这个复杂问题，分解为"MediaPipe看关键点"+"数学公式算特征"+"浅层模型分类"三个简单子问题。

**创新点对比**：
| 维度 | 端到端深度学习 | 本项目2-stage方案 |
|------|-------------|---------------|
| 训练数据量 | 5000-50000张 | 1000-3000帧 |
| 模型大小 | 10-100MB | 3MB（纯C代码） |
| 推理框架 | PyTorch/ONNX Runtime | 无（纯C，单文件编译） |
| 边缘部署难度 | 需交叉编译DL框架 | gcc即可编译 |
| 可解释性 | 黑盒 | 每维特征有物理含义 |
| 小样本泛化 | 差 | 好（关键点级特征鲁棒） |

**层面二：98维特征向量的针对性设计**

不是简单地将33关键点坐标展平（33×4=132维）作为特征，而是**根据人体运动学原理**设计了6个子模块，维度从132降至98但信息密度更高：

| 子模块 | 物理含义 | 为什么这样设计 |
|--------|---------|--------------|
| 躯干基础(6维) | 质心、躯干角度 | 行走→躺卧时质心高度变化最显著 |
| 关节点归一化(66维) | 相对质心的姿态坐标 | 移除人体在画面中位置偏移的影响 |
| 身体角度(8维) | 膝/肘弯曲角度 | 坐/躺/站的膝盖角度特征区分度高 |
| 姿态结构(8维) | 宽高比、对称性 | 跌倒时姿态结构发生突变 |
| 运动特征(4维) | 帧间位移/速度 | 行走vs静止的关键区分特征 |
| 传感器槽(6维) | 加速度/心率/体温 | 为多模态融合预留接口 |

**层面三：m2cgen全链路模型导出与边缘部署**

这是当前业内较少使用但在本场景中恰好最优的方法：

```
Python训练 (scikit-learn) 
    → m2cgen导出纯C代码（84,000行，无任何依赖） 
    → CMake交叉编译为ARM/RISC-V二进制 
    → Milk-V Duo S上直接运行（<2ms/帧推理）
```

相比常规方案的优势：
- **vs. TensorFlow Lite Micro**：不需要20MB+的TF Lite运行时，不需要flatbuffer模型解析
- **vs. ONNX Runtime**：不需要ONNX运行时（Duo S上难以编译部署）
- **vs. MicroTVM**：不需要复杂的AutoTVM调优流程

**准确性验证**：经`test_deploy.c` + `test_deploy_duos.c`双重验证，C实现与Python推理结果**完全一致**（98/98特征匹配，分类结果一致）。

#### 5.2 对标准确性对比

| 指标 | 业内常用方案(ResNet18微调) | 本项目(RandomForest on 98-dim features) |
|------|--------------------------|----------------------------------------|
| 训练时间 | ~2小时 (GPU) | ~5分钟 (CPU) |
| 模型大小 | 45MB (PyTorch) | 3MB (纯C代码) |
| 推理速度(Python) | ~50ms/帧 (CPU) | <1ms/帧 (CPU) |
| 推理速度(C) | 难以部署(需框架) | <2ms/帧 (RISC-V 1GHz) |
| 训练数据需求 | 10,000+ 图片 | 2,000+ 帧特征 |
| 跌倒检测准确率 | ~92% | ~90% |
| 边缘端部署复杂度 | 高（需PyTorch/ONNX Runtime） | 极低（单文件C编译） |
| 可解释性 | 黑盒 | 白盒（每维特征含义明确） |

**自评：5分**（在特定任务上——百元级微边缘设备的实时姿态分类——推理速度/部署友好度显著优于业内常用深度学习方法，准确率接近）

#### 6.3 系统可扩展性设计

**（1）接口扩展**
- UART接口：预留ESP32-S3传感器子节点接入通道
- I2C接口：支持扩展更多I2C传感器（如温湿度、气体传感器）
- GPIO接口：预留4路GPIO用于扩展本地告警设备
- USB接口：支持扩展USB摄像头、USB 4G模块
- WiFi接口：MQTT/HTTP协议自适应切换

**（2）功能扩展**
- **传感器扩展**：在现有MPU6050/MAX30102/MLX90614基础上，预留了6维传感器特征槽，可无缝接入：
  - 环境传感器（温度、湿度、烟雾、CO）
  - 定位模块（GPS/北斗，用于户外走失场景）
  - 语音模块（TTS语音提醒，如"请及时服药"）
- **模型扩展**：
  - 98维特征向量为标准接口，任何scikit-learn兼容分类器（SVM、XGBoost、LightGBM）均可替换RandomForest
  - `export_to_c.py`支持一键导出为不同格式（ONNX/TFLite/C Code），适配不同硬件平台
- **告警扩展**：
  - 支持添加多个告警级别（目前4级：正常/提醒/警告/严重）
  - 告警渠道可扩展：微信模板消息、短信、语音电话、邮件、MQTT订阅
