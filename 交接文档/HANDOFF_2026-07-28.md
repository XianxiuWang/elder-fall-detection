### 2.2 P0 缺陷修复

基于 Session #4 数据识别的两个核心问题：

**问题 A：风险漂移（Risk Drift）**
- 根因：`_compute_double_support_ratio()` 在静止站立时返回 ~1.0（双脚同高 → 100%双支撑），传入 `_gait_risk()` → `ds_r=100`，每帧贡献 5 分到总分，EMA 永不衰减
- 修复：在 `fall_predictor.py` 中：
  - 添加 `_is_walking` 状态追踪（3秒无步态 → 静止）
  - `_gait_risk()` 非行走时返回 0.0
  - 添加风险稳定性衰减：连续 60 帧稳定后，风险分向站立基线（~10）衰减

**问题 B：ML 模型缺少"站立"类**
- 根因：5 分类模型（Fall/SitDown/StandUp/Walking/WakeUp）无"Idle/Standing"类，静止站立帧被映射到 "Fall"（84.5% 预测为 Fall）
- 修复：在 `e2e_fall_monitor.py` 中添加 `_is_idle_standing()` 前置过滤器：
  - 躯干摇摆 < 5°
  - 躯干倾斜 < 12°
  - COM 移动速度 < 0.02
  - 包围盒比 0.25-0.85（排除倒地/侧卧）
  - 头在髋之上
  - 满足条件时抑制 ML fall_trigger

## 5. 踩过的坑 ⛔ 绝对不要再踩

### 坑 1：OpenCV 5.0 vs 4.x 不兼容 ✅ 已根治
- **症状**：`putText` 崩溃 `cv2.error: OpenCV(5.0.0) ... Scalar is not a 3 or 4 element vector`
- **根因**：`FallConfig.load()` JSON 反序列化后 `putText` 颜色参数是字符串 `'(128,128,128)'` 而非 tuple
- **教训**：conda `fall` 环境是 **OpenCV 5.0.0**（不是文档里写的 4.5.5），不要假设版本
- **修复**：`fall_config.py` v2.1 — `_make_json_safe()` 将 tuple 序列化为 list（JSON 原生），`_parse_json_loaded()` 兼容旧版字符串元组

### 坑 2：MediaPipe 与 OpenCV 5 的兼容性
- `fall` 环境用 `mediapipe==0.10.14`，与 OpenCV 5.0.0 兼容，不需要降级
- TensorFlow Lite 有 WARNING 但无实际影响

### 坑 3：风险漂移——不要重复发明 EMA
- EMA 不适合"应该归零"的信号。当基础信号持续高位时，EMA 永远不归零
- **正确做法**：先判断上下文（是否在行走），非行走状态直接 suppress 步态相关风险
- 风险衰减需要"判断条件"触发，不能只靠 EMA 自己

### 坑 4：数据库还在写旧的 session #4 的 alert 截图
- Session #5 运行时，`alerts/` 目录下仍有的旧截图（session #4 的）
- 不过新 session 的告警数量已大幅减少

### 坑 5：笔记本摄像头初始化慢
- OpenCV `cv2.VideoCapture(0)` 在 Windows 上首次打开可能需 10-15 秒
- 不要在这个阶段手动 Q 退出，耐心等待
