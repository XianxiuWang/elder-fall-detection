### 2.1 V8 模型训练定稿（补 SitDown 短板）

**背景**：V7 的 SitDown 召回率仅 54.9% ± 24.5%（源文件只有 23 个动作段，样本全靠滑窗硬凑）。用户提供新数据 `F:\动作数据集\50个坐下的动作.mp4`（50 个坐下动作）。

**动作**：
- 写 `training/extract_sitdown.py`：照搬 standup_wakeup_v2 分段逻辑（姿态丢失 gap≥4帧硬切、静帧位移<0.005×12帧软切），class_id=1，输出 `data/custom_sitdown/sitdown_XXXX.npz`
- 写 `training/train_6class_v8.py`（v7 + 三处改动）：新增 custom_sitdown 数据源、输出 v8 模型、移植 v6 的事件级评估到每折验证集

**v8 结果（5折 GroupKFold）**：
- CV Acc 90.44% ± 2.17%，F1 90.45%
- **SitDown 召回 54.9% → 82.67% ± 6.66%** ✅
- SitDown 样本 1782 → 3501；数据源 6→8；总样本 14030→16343
- 事件级 Fall：TP=263 FP=82 FN=9，precision 0.762 / recall 0.967 / F1 0.853，误报 8.20/千窗
- Fall AP 0.965 / ROC-AUC 0.985

**严格消融**（`train_6class_ablation_v6data.py`，v6 数据 + 同样 5 折协议）：
- v6 CV Acc 94.15%（证明原报告 96.16% 是单折虚高），但短板类爆炸：SitDown 61.7%±28%、StandUp 58.7%±47.9%、WakeUp 74.2%±37.9%
- **结论：v8 用 3.7pp 总准确率换全部 6 类稳定，v8 胜出**

## 5. 今天新增的坑 —— 绝对不要再踩

### 🔴 坑1：训练/部署特征维度失配（59维 vs 51维 vs 42维）
**现象**：模型训练好好的，部署加载就崩 `StandardScaler is expecting 59 features`
**根因**：v7/v8 训练时**丢掉了 8 个 tilt 特征**（59=42base+9temporal+8tilt → 51=42+9），而 `fall_inference.py` 仍带 tilt 块；src/ 旧链路更老（42 维 base）
**修复**：部署端删 tilt 块对齐 51 维；用 `verify_deploy_align.py` 逐维校验（实测 maxdiff 6.7e-10）
**教训**：**改一次特征，训练端和部署端必须同步改 + 跑对齐验证脚本**，否则部署必崩

### 🔴 坑2：ema_alpha 语义容易理解反
**正确语义**：**alpha 越低 = 平滑越重 = 瞬时误报尖峰被压掉、误报越少，但响应略慢**（~0.8s vs 0.4s），召回几乎不掉（跌倒事件是持续多窗的）
**教训**：之前给用户解释成"越低越贴原始值/响应越快"是错的，已更正。阈值扫描结论：alpha=0.15 全面最优

### 🟠 坑3：git 首次 add 误暂存数据文件 → .git 膨胀
**现象**：`git init` 后第一次 `git add -A` 把 data/ 和 alerts/ 的几千个 npz/jpg 都暂存了，.git 膨胀到 96MB
**修复**：补 `.gitignore` → `git reset` → 重新 `git add -A` → `git reflog expire --expire=now --all && git gc --prune=now --aggressive`，.git 降到 1.0MB
**教训**：**大目录项目先写好 .gitignore 再 add**；reset 不删已写进 .git/objects 的 blob，必须 gc --prune=now 才回收

### 🟡 坑4：git 中文路径显示乱码/带引号
**现象**：`git status` / `git ls-files` 中文文件名显示成 `\344\347...` 或带引号
**修复**：`git config core.quotepath false`
