## 二、我的 3 个接口合约（与后端田靖宇的硬约定）

> 统一规则：HTTP/1.1 + JSON，前缀 `/api/v1/`，返回 `{code, message, data}`（200/400/500）。
> 硬件输出必须严格按此入参出参，禁止自定义格式。

### 1. POST `/api/v1/pose-analysis/simulate` — 姿态步态模拟/分析结果

请求体：
```json
{ "elderly_id": 1, "action_type": "high_risk" }
```
`action_type` 枚举：`normal`（正常步态）/ `unstable`（异常步态）/ `high_risk`（高风险步态）

返回 data：
```json
{ "walking_speed": 0.6, "step_length": 0.35, "body_sway": 10, "balance_score": 55, "gait_score": 45 }
```

### 2. POST `/api/v1/gait-data/` — 原始步态数据上传 ⭐核心

用途：边缘 OPI 推理完成后，上传原始步态参数入库（InfluxDB 时序）

请求体（4 个字段，固定）：
```json
{ "elderly_id": 1, "walking_speed": 1.2, "step_length": 0.65, "body_sway": 5, "balance_score": 95 }
```

### 3. POST `/api/v1/fall-prediction/run` — 跌倒风险预测计算

请求体：
```json
{ "elderly_id": 1 }
```
返回 data：
```json
{ "risk_score": 85, "risk_level": "高风险", "reason": ["步速持续下降", "身体晃动幅度增加"] }
```
