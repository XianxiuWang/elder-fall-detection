## 5. 踩过的坑 ⛔ 绝对不要再踩

### 坑 1：`conda run` 不适合长任务
- **症状**：进程没死但输出冻结，日志不更新
- **原因**：conda run 的 stdout/stderr 管道在长时间运行后可能断开或缓冲溢出
- **教训**：长任务（>2分钟）不要用 `conda run`。让用户在已激活环境的终端直接跑，或用 `.bat` 批处理
- **解决**：写一个 `.bat` 文件给用户双击运行，比远程执行可靠得多

### 坑 2：六分类模型在真实摔倒视频上表现差
- **症状**：纯摔倒视频被判为 WakeUp（89.6%），Fall 概率仅 1.5%
- **根因**：训练数据 141 个 npz 中的 Fall 样本主要来自学术数据集（Le2i、URFD），姿态标准化，缺少"五花八门"式真实摔倒
- **教训**：模型在训练集分布内的数据上准确率高（97.87%），不代表在新分布上也好。需要持续用真实数据扩充
- **修复方向**：用本次三个视频扩充 Fall 类 + 考虑数据增强（旋转、缩放、平移）

### 坑 3：OpenCV VideoCapture vs RTSP URL
- `cv2.VideoCapture(filename)` 和 `cv2.VideoCapture(rtsp_url)` 行为不同：
  - 视频文件：播完返回 `ret=False`，可以直接 `break`
  - RTSP 摄像头：丢帧也返回 `ret=False`，但不能 break，需要重试
- e2e v5.0 已用 `_is_video_file` 标志区分两种情况

### 坑 4：PowerShell 不支持 `&&`、`timeout` 等命令
- 在 Windows 上写检查脚本时，不要用 `&&` 连接命令或用 `timeout`
- 用 `;` 分隔，或写 `.bat` 文件，或用 `powershell Start-Sleep`

### 坑 5：`FallConfig.load()` 反序列化（已根治，但记录备查）
- Opencv 5.0.0 不接受字符串格式的颜色参数
- 修复在 `fall_config.py` v2.1：tuple → JSON 数组序列化

### 9.2 新增模块：`src/fall_early_warning.py` v1.0 ✅

**设计理念**：不等摔倒，追踪"失衡恶化过程"。当步态稳定性特征出现多维度同步退化时，提前预警。

**六指标预测体系**：

| # | 指标 | 计算方式 | 生物力学含义 | WARN 阈值 | DANGER 阈值 |
|---|------|----------|-------------|-----------|-------------|
| 1 | COM 摇摆加速 | 躯干横向偏移的加速度 | 平衡恶化中 | 0.004 | 0.008 |
| 2 | 步宽变异 | 双踝距离的变异系数 (CV) | 站立不稳加剧 | 15% | 25% |
| 3 | 躯倾角速度 | 躯干-垂直角的变化率 (°/s) | 即将倾倒 | 15°/s | 30°/s |
| 4 | 支撑面缩小 | 双足包围盒面积缩减率 | 基底支撑崩溃 | 15%/s | 30%/s |
| 5 | 手臂扑腾 | 腕部速度突发峰值 | 试图恢复平衡 | 0.08 | 0.15 |
| 6 | 步态节律 | 步频间隔的 CV | 行走节奏破碎 | 25% | 40% |

**投票机制**：
```
≥3 指标同时恶化 → CRITICAL (严重预警, 风险分≥70)
≥2 指标同时恶化 → WARNING  (预警, 风险分≥50)
≥1 指标触发     → WATCH    (关注, 风险分≥30)
```

**与 FallPredictor 的区别**：
- `FallPredictor`：检测已经发生的摔倒（事后），分析瞬时姿态+空间特征
- `FallEarlyWarning`：预测即将发生的摔倒（事前），分析趋势线+加速度+多维同步退化

### 9.3 e2e v5.1 集成 ✅

**改动清单**：
- 新增 import → `from .fall_early_warning import FallEarlyWarning`
- `_init_detectors()` → 初始化 `self.early_warning = FallEarlyWarning(fps=self.fps)`

## 11. 新增踩坑记录 ⛔

### 坑 6：训练数据类缺失导致 ML 完全跑偏
- **症状**：WakeUp 类训练数据为 0，模型在特征空间中将陌生摔倒姿态误映射到 WakeUp（因为 WakeUp 就是躺着→起身，与摔倒后的肢体姿态接近）
- **根因**：`custom_6class/` 由 Fall 提取脚本生成，但未从 `custom_5class/` 迁移 WakeUp 数据
- **教训**：**任何数据迁移/扩充后，必须逐类核对文件计数**。写一个简单的 `count_per_class.py` 脚本，每次训练前先 run
- **修复**：从 `custom_5class/` 恢复 WakeUp 文件，重训后 Fall 概率从 1.5%→99.76%

### 坑 7：`classification_report` 不接受部分类别
- **症状**：`ValueError: Number of classes, 5, does not match size of target_names, 6`
- **根因**：sklearn 的 `classification_report(target_names=[全部6类])` 要求验证集必须包含全部类别
- **修复**：动态计算 `present_labels = sorted(set(y_val) | set(y_pred))`，传入 `labels` 参数

### 坑 8：Early Warning vs Fall Prediction 是两套互补系统，不是替代
- FallPredictor（事后检测）和 FallEarlyWarning（事前预测）的指标体系和计算方法完全不同
- 前者看瞬时姿态偏移，后者看趋势线加速度和多指标同步退化
- **必须两者同时运行**，HUD 上并排显示。事前的预警可以提前通知家属/护工，事后检测确认摔倒不可避免时触发紧急告警
