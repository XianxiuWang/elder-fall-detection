### 4.2 萤石 C6c RTSP 对接

- 当前只通过 `cv2.VideoCapture(0)` 打开 USB 摄像头
- 需要改成 `cv2.VideoCapture("rtsp://admin:password@192.168.x.x:554/...")`
- 建议通过命令行参数 `--camera rtsp://...` 或 `--camera 0` 切换

### 4.3 性能调优（OPI5 专用）
- `MODEL_COMPLEXITY = 1` 目前适合 RK3588S
- 如果帧率不够，降到 `0`
- `SKIP_FRAMES = 3` 可以调到 `4` 或 `5` 降低负载
- 如果 4GB 内存紧张，考虑：MediaPipe 用 `model_complexity=0`，特征提取减少 `POSE_CHUNK`

## 5. 踩过的坑 —— 绝对不要再踩

### 🔴 坑1：SKIP_FRAMES 跳帧导致画面闪烁
**现象**：画面上的骨架、标签、步态面板一明一灭交替闪烁
**原因**：`SKIP_FRAMES=3` 每 3 帧才跑一次 MediaPipe，剩下 2 帧直接 `continue` 跳过所有绘制
**修复**：
- 引入 `disp_*` 缓存变量（disp_label, disp_color, disp_gait, disp_sent, disp_progress, disp_fall_border）
- 处理帧更新缓存变量，跳帧时只跳过推理，不跳过绘制
- **所有绘制（骨架、标签、面板、进度条、状态栏）统一放在循环末尾**，每帧都跑
- **骨架用 `last_pose_result` 缓存**，跳帧时重绘上一次的骨架

**教训**：任何跳帧优化，显示层必须和目标帧率解耦。见 `cv_client.py` 中的统一绘制块（标记 `Unified Draw — every frame, zero flicker`）。

### 🔴 坑2：时序过滤器 switch_pending 逻辑缺陷
**现象**：标签在 Walking/Standing 之间疯狂跳，参数调到很大也没用
**原因**：旧逻辑中，只要有一帧回到当前标签，`switch_pending` 计数器就归零。Walking+Standing 交替出现时，永远凑不够 MIN_DURATION。
**修复**：完全废弃 switch_pending 机制，换成 **70/30 滞后投票阈值**：
```python
# 切换到新标签：新标签必须在投票窗口占 >70%
# 留在当前标签：只要当前标签还占 >30%
if new_ratio > 0.7 and cur_ratio < 0.3:
    self.cur_label = new_label
```
**代码位置**：`fall_inference.py` → `TemporalFilter.update()` → "滞后切换保护" 注释块

### 🔴 坑3：V5 自由落体确认锁强制翻转标签
**现象**：Fall 检测不稳定，偶尔触发后又立刻跳回 Standing
**原因**：当下降速度不达标时，代码直接执行 `self.cur_label = alt`，绕过了所有切换保护机制
**修复**：不强制翻转，改为 `self.fall_ctr = max(0, self.fall_ctr - 4)`，让正常投票机制接管

### 🟠 坑4：EMA 平滑参数选择
**选择**：`alpha = 0.3`（新值占 30%，旧值占 70%）
**为什么是这个值**：
- 0.5 太重，新帧变化太大时标签仍会跳
- 0.1 太轻，响应太慢
- 0.3 是折中点：普通行走切换约 2-3 秒，Fall 检测约 1 秒

### 🟠 坑5：protobuf 版本警告刷屏
**现象**：终端被 `SymbolDatabase.GetPrototype() is deprecated` 刷爆
**修复**：在 `cv_client.py` 开头加：
```python
import warnings
warnings.filterwarnings("ignore", category=UserWarning, module="google.protobuf")
os.environ["GLOG_minloglevel"] = "2"
```

### 🟡 坑6：OPI5 4GB 内存极限
**注意**：RK3588S 的 NPU（6 TOPS）很香，但 4GB LPDDR5 同时跑 MediaPipe + XGBoost + DeepFace 可能内存不够。如果未来要集成 DeepFace（王权瑶的模块），建议：
- 两个模型分时运行（人脸检测 1Hz，跌倒检测 10Hz）
- 或者人脸跑在另一个设备上
- 模型量化：XGBoost 转 ONNX 可以省内存
