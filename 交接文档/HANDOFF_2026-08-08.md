## 我们在做什么

**目标**：让跌倒检测系统只对"真跌倒"告警，不对弯腰、蹲下、捡东西告警。

**核心矛盾**：MediaPipe Pose 只输出 33 个 2D 关键点 (x,y)。2D 视角下，"人弯腰捡钱"和"人向前摔倒"的关键点轨迹几乎一模一样——系统看不到"这个下降是主动控制还是被动坠落"。

**我们的解决方案**：在时序过滤器中加入**自由落体判别器**，利用下降速度区分可控动作 vs 真跌倒——真跌倒躯干坠落 ~2-3 person-heights/sec，弯腰/蹲下是主动控制 ~0.3-0.7 heights/sec。

### ② 自由落体判别器 (Free-fall Discriminator)

在 `video_inference.py` 的 `TemporalFilter` 中新增：

**函数** `compute_max_descent_speed(window, effective_fps)`:
- 输入：30 帧关键点窗口 (30×33×3)
- 计算髋部中点 (keypoint 23+24) / person_height 的归一化下降速度
- 用前 1/3 帧锁定 person_height 参考值（避免下降中躯干拉长导致速度稀释）
- 返回：最大下降速度 (person-heights/sec)，-1 表示低可见性无法计算

**参数**:
```python
FALL_DESCENT_THRESH = 0.80  # person-heights/sec，低于此值判为可控动作
```

**单元测试** (9 场景全部通过):
| 场景 | 速度 | 判定 |
|------|:---:|------|
| 真跌倒 (Falling Down) | 2.80 | ✅ 放行 |
| 弯腰 (Slow Bend Reach) | 0.53 | ✅ 阻挡 |
| 深蹲 (Deep Squat) | 0.67 | ✅ 阻挡 |
| 从椅子滑落 (Slip Off Chair) | 1.50 | ✅ 放行（不漏） |
| 完全静止 | 0.00 | ✅ 阻挡 |
| 低可见性（关键点丢失） | -1.00 | ✅ 不干预 |

### ③ V4 判别器生效 → 摔倒视频碎片化副作用

V4 对**每个窗口**都检查下降速度。真摔倒视频中：
- 摔倒过程有多阶段：弯腰/低头 → 失衡 → 快速坠落 → 触地静止
- "弯腰"和"低头"阶段下降速度 < 0.80 → 被推翻 → Fall 事件断开

**结果**：50种摔倒 1事件→10碎片，50个摔倒 1事件→12碎片。覆盖率完好但用户体验不可接受。

### ④ V5 确认锁机制 (Confirmation Lock) 🔥 最终版本

**核心思路**：前 3 个窗口连续快速下降 → 锁定整个 Fall 事件，锁定后不再检查速度。

新增状态变量：
```python
self.fall_confirmed = False      # 当前 Fall 事件是否已锁定
self.descent_ok_count = 0        # 连续快速下降窗口计数 (>=3 锁定)
```

**逻辑流程**:
```
Fall 帧到达:
  if 未确认:
    if 下降速度 >= 0.80:  descent_ok_count++
    if descent_ok_count >= 3:  确认锁定 ✅
    else:  推翻 Fall → 重置计数
  else:  已确认 → 跳过速度检查，保持 Fall

离开 Fall 状态 → 自动解锁（下次进入重新验证）
```

**单元测试** (5 场景全部通过):
1. ✅ 真跌倒：3 帧锁定，后续慢帧全放行（无碎片）
2. ✅ 慢弯腰：永远达 3 帧 → 被挡
3. ✅ 中断恢复：慢帧打断 → 重置 → 需重新 3 帧
4. ✅ 锁定容忍：锁定后慢帧不推翻
5. ✅ 退出解锁：离开 Fall 自动重置

## ⚠️ 绝对不要再踩的坑

### 时序过滤器 (来从 08-06)

1. **label_dur 死锁**：不要用同一个变量既计数"等"又计数"判"。**用独立的 `switch_pending`。**

2. **Fall hold 必须经过投票**：`fall_ctr > 0` 不能单方面推翻投票结果。最低要求：窗口内 ≥2 票投了 Fall。

3. *(已修复)* **v2 的 0 Fall 是 Bug 假象**，不是性能好——label_dur 死锁掩盖了真实误报。

### 自由落体判别器 (今天新增)

4. **对每个窗口检查下降速度会导致事件碎片化**：真跌倒多阶段（弯腰→失衡→坠落→静止），前两阶段速度不够快会被误推翻。
   **方案**：用确认锁机制（V5），前 3 窗口确认后锁定跳过后续检查。

5. **person_height 参考值必须在下降发生前锁定**：如果从整个窗口计算中位数，下降过程中髋部下坠→躯干拉长，导致"下降速度"被稀释成原来的 60-70%。
   **方案**：只用前 1/3 帧（下降前）的 person_height。

6. **MediaPipe 关键点是归一化坐标 [0,1]**：person_h_med 阈值为 0.015（不是像素 10）。混淆会导致所有窗口退回 -1（跳过检查）。

### 训练/推理

7. **训练与推理的特征提取器必须严格一致**：V6 是 59 维（42 base + 9 temporal + 8 tilt），推理脚本改了维度才能加载。

8. **FFT 频域特征在 30 帧窗口有害**：窗口太短频率分辨率不够 → 纯噪声。不要尝试。

9. **SMOTE 对时空数据有害**：在 51 维姿态空间中插值生成假数据 → 不符合真实物理约束。

10. **中文路径 + `conda run` 的 GBK 编码** → 用 `d:\Anaconda3\envs\fall\python.exe -u` 直接运行，脚本头加 `sys.stdout.reconfigure(encoding='utf-8')`。

11. **`cap.set(CAP_PROP_POS_FRAMES)` 对 H.264 极慢** → 按簇跳帧+簇内顺序读。

12. **深度图 PNG 对 MediaPipe Pose 完全无效** → 不要在这上面浪费时间。

