### 2.3 个性化步态基线 v1.0 ✅ （核心创新）

**新增文件**: `E:\老人跌倒\src\personalized_baseline.py` (~800 行)

这是"方向一"创新的落地——从"检测跌倒"升级为"预测跌倒风险"：

| 特性 | 实现 |
|------|------|
| 个人步态指纹 | 7 项核心指标 × 每人独立 μ/σ 分布 |
| Z-score 偏离检测 | 3 级阈值：WARN(1.5σ) / ALERT(2.5σ) / DANGER(3.5σ) |
| 临床显著性 | 步速↓0.1m/s、摇摆↑3° 等医学化阈值 |
| EMA 慢速自适应 | α=0.0005，模拟自然老化 ~0.2%/月 |
| 持久化 | JSON 存储到 `E:\老人跌倒\baselines\`，跨会话不丢失 |
| 校准期 | 自动收集 ~30 帧行走数据后自动激活 |

**核心思想**：不是跨人群比对（"你的步态比人群平均差"），而是和"过去的自己"比（"你今天的步态偏离自己常态 3.5σ"）。这在医学上有论文支撑（Hausdorff et al.）。

## 五、踩过的坑（绝对不要再踩）

### 坑 1: Windows 控制台编码导致 emoji 乱码

- **症状**: `print("✅ 测试通过")` 在 Windows CMD 中输出乱码
- **解决**: 用英文输出或用 `chcp 65001` 切换到 UTF-8
- **教训**: 跨平台 Python 脚本不要用 emoji，用纯 ASCII 或英文标记

### 坑 2: 系统代理干扰所有网络请求

- **症状**: pip/conda 莫名其妙 SSL 错误、连接超时、GitHub 下载失败
- **解决**: **每次开新 CMD 先跑**：
  ```cmd
  set HTTP_PROXY=
  set HTTPS_PROXY=
  set http_proxy=
  set https_proxy=
  ```
- **教训**: 装了代理工具一定要关掉或设好路由规则。这个坑反复踩了 N 次。

### 坑 3: ultralytics 每次都从 GitHub 下载模型

- **症状**: `YOLO("yolov8n.pt")` 每次都下载，代理不稳定时卡死
- **解决**: 查找 `C:\Users\wangxianxiu\.cache\torch\hub\ultralytics_yolov8_master\yolov8n.pt` 缓存路径，手动传入
- **教训**: 任何模型加载都要考虑离线/缓存场景，不要依赖在线下载

### 坑 4: MediaPipe Pose Python API 只能输出单人

- **症状**: `mp_pose.Pose()` 返回 `pose_landmarks` 是单人的，多人场景只检测一个人
- **解决**: 先用 YOLO 检测所有人 bbox，crop 每人 ROI，逐个推理 MediaPipe
- **教训**: 读 API 文档前不要假设"多人=多人输出"，先确认 API 能力边界

### 坑 5: conda activate 在 `cmd /c` 中行为怪异

- **症状**: `cmd /c "conda activate fall & python script.py"` 有时找不到 conda 环境
- **解决**: 用 `conda activate fall &` 后跟单 `&`（不用 `&&`），或者在命令前 `call conda activate fall`
- **教训**: conda 的 activate 不是真正的可执行文件，是 shell 函数；在 subprocess 中传递命令要小心

### 坑 6: 校准阈值硬编码不匹配

- **症状**: `add_calibration()` 硬编码阈值 100，但 `calibration_min_walking` 设为 30，导致校准永远不激活
- **解决**: 统一使用 `self.calibration_min_walking` 作为阈值
- **教训**: 配置值和代码中要统一用变量，不要硬编码多个副本

### 坑 7: GaitMetricExtractor 没有 `frame_width/height` 参数

- **症状**: 创建 `GaitMetricExtractor()` 时传了 `frame_width` 和 `frame_height`，报参数不存在
- **根因**: `GaitMetricExtractor.__init__` 的签名是 `(prefix="", min_samples=4)`，没有画布尺寸参数
- **解决**: 不传这两个参数，`extract()` 内部接受 `landmarks` 和 `bbox` 参数
- **教训**: 调用别人写的类前先看 `__init__` 签名

## 九、v6.1 关键设计决策

| 决策 | 理由 |
|------|------|
| 每人一个 PersonalBaseline 实例 | 基线是"个人指纹"，不能跨人共享 |
| 每帧都喂入基线 | 基线内部有 EMA 平滑，不会因单帧波动误报 |
| 基线在 `_process_person()` 中更新 | 紧跟在 gait_trend 之后，确保数据一致性 |
| 丢失跟踪也更新基线 | 丢失前最后一帧可能包含关键偏离信息 |
| 退出时自动保存基线 | 跨会话持久化，重启不丢失 |
| 单人模式也集成基线 | 保证一致性，单人场景也有创新层覆盖 |
| EMA α=0.0005 | 对应自然老化速率 ~0.2%/月，不会被短期波动污染基线 |
