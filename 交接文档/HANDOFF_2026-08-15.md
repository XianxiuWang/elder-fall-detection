## 3. 接口合约（王纤秀 3 个接口，与田靖宇后端的硬约定）⚠️重要

统一：HTTP/1.1 + JSON，前缀 `/api/v1/`，返回 `{code, message, data}`

### 1. POST `/api/v1/pose-analysis/simulate` — 姿态步态模拟
请求：`{"elderly_id":1,"action_type":"high_risk"}`（枚举 normal/unstable/high_risk）
返回 data：walking_speed, step_length, body_sway, balance_score, gait_score

### 2. POST `/api/v1/gait-data/` — 原始步态上传 ⭐核心（我方客户端对接这个）
请求（4 字段，扁平，单位已定）：
```json
{
  "elderly_id": 1,
  "walking_speed": 1.2,   // m/s
  "step_length": 0.65,    // m
  "body_sway": 5,         // 归一化×100
  "balance_score": 95     // 0-100
}
```

### 3. POST `/api/v1/fall-prediction/run` — 跌倒风险预测
请求：`{"elderly_id":1}`；返回 data：`{"risk_score":85,"risk_level":"高风险","reason":[...]}`

## 6. 今天新增的坑 —— 绝对不要再踩

### 🔴 坑1：cv_client.py 接口完全不符合 API 规范 V1.0
**现象**：代码里是旧格式 `/api/gait-data` + 嵌套 `gait_data{speed,sway,gait_score}`，和规范 V1.0（`/api/v1/gait-data/` + 扁平 `walking_speed/body_sway/balance_score`）**字段名、结构、URL 全对不上**
**教训**：**代码接口必须逐字对照 API 规范文档核对**，别凭记忆写；改完 grep 残留旧字段名 + py_compile 语法验证

### 🔴 坑2：walking_speed 单位差 100 倍
**现象**：代码算的是 cm/s（80~120），规范示例 1.2 是 m/s，联调时才发现差 100 倍
**根因**：API 文档不写单位，各模块各按各的猜
**修复**：用 `PIXEL_TO_CM=180` 标定系数换算，walking_speed ÷100、step_length ×1.8
**教训**：**接口字段必须明确单位/量纲**，文档没写就主动定 + 发群确认，别等联调翻车

### 🟠 坑3：git push 走 443 端口被代理干扰
**现象**：`git push` 报 `NativeCommandError`（实际是 git 走 stderr 输出 + 443 被代理干扰）
**修复**：`ssh -T git@github.com` 走 **22 端口**（绕开被代理干扰的 443）
**教训**：装了 Clash/V2Ray 时，git 走 22 端口更稳；push 输出走 stderr 是正常的，看最后一行 `xxxx..xxxx main -> main` 即成功

### 🟠 坑4：.gitignore 优先级高于 git-lfs track
**现象**：track 了 `*.pkl` 但 LFS 不生效，模型文件永远不会被追踪
**根因**：`.gitignore` 先排除 `*.pkl`，ignore 优先级高于 LFS track
**修复**：`.gitignore` 移除这些类型的排除
**教训**：**git-lfs 前先检查 .gitignore 是否冲突**

### 🟡 坑5：FastAPI 路由尾斜杠敏感
**现象**：后端定义 `/x/`、客户端打 `/x` → 307 重定向；反过来 → 404
**教训**：**文档、后端、客户端三方斜杠必须一字不差**；文档里 gait-data 带斜杠、pose-analysis 不带，联调前必须统一

> 更早的坑（特征维度失配 59/51/42 维、ema_alpha 语义、git add 误暂存数据膨胀、中文路径乱码）见 `HANDOFF_2026-08-14.md` 第 5 节。
